## 1. 项目概览

这是一个 **Unity 官方开源教学项目**，类型是第三人称 3D 烹饪冒险游戏。它的代码质量很高、结构清晰，特别适合用来学习**中型 Unity 项目的工程化组织方式**。

| 维度 | 内容 |
|------|------|
| 渲染管线 | URP（Universal Render Pipeline） |
| 输入系统 | 新版 Input System（`GameInput`，自动生成的 C# 类） |
| 场景加载 | **Addressables**（可寻址资源系统） |
| 代码组织 | 大量使用 **ScriptableObject（SO）** 做"数据与逻辑分离" |
| 核心玩法 | 移动、跳跃、滑铲、攻击、与 NPC 对话、接任务、收集食材、做饭 |

**一句话总结架构**：这是一个「**数据驱动**」的项目——行为逻辑大多不写在代码里，而是通过把各种 `*SO`（ScriptableObject 资产）在 Inspector 里"拼装"出来的。

## 2. 核心架构思想（先记住这 3 个概念）

在开始读代码前，先理解这三个贯穿全项目的设计模式：

### 2.1 ScriptableObject 事件系统（事件解耦）

项目的 `Events` 文件夹实现了 **EventChannel（事件通道）** 模式：

- 一个 `VoidEventChannelSO` / `IntEventChannelSO` 就是一个"广播电台"。
- 发射方调用 `.RaiseEvent(...)`（只管广播，不知道谁在听）。
- 监听方在 `OnEnable` 里订阅 `OnEventRaised`，`OnDisable` 里取消订阅。

```
发射方 ──RaiseEvent──▶ EventChannelSO ──OnEventRaised──▶ 监听方
（例如拾取物品）      （一个 SO 资产）        （例如刷新 UI 背包）
```

**好处**：任意两个模块之间不需要互相引用，不会出现"蜘蛛网式依赖"。

### 2.2 数据驱动状态机（主角的"大脑"）

主角的一切行为由 `StateMachine` 驱动，但**状态和转换规则不在代码里**，而是存在 `PigChef_TransitionTable.asset` 这个 SO 资产里：

- `States/`（状态）：Idle、Walking、JumpAscending、Sliding、Attacking…
- `Actions/`（行为）：状态内每帧/进出时执行的逻辑
- `Conditions/`（条件）：用来判断"是否切换到另一个状态"

核心代码只有 6 个类（`Assets/Scripts/StateMachine/Core/`）：

| 文件 | 作用 |
|------|------|
| `StateMachine.cs` | 挂在角色身上的入口，每帧驱动状态机 |
| `State.cs` | 一个运行时状态 = Actions 数组 + Transitions 数组 |
| `StateAction.cs` | 状态行为（OnStateEnter / OnUpdate / OnStateExit） |
| `StateCondition.cs` | 状态条件（每个条件有缓存，转换后清除） |
| `StateTransition.cs` | 状态转换（条件全部满足才转换） |
| `IStateComponent.cs` | 统一接口，让 Action 和 Condition 共用生命周期 |

**建议先看 `StateMachine.cs` 的 `Update()`**，整个状态机就三行核心逻辑：
1. 检查能否转换 → 2. 转换则退旧进新 → 3. 执行当前状态的 `OnUpdate`。

### 2.3 RuntimeAnchor（运行时锚点）

`RuntimeAnchors/TransformAnchor.cs`：一个 SO 资产在运行时"指向"场景里的某个 Transform（比如主摄像机）。任何脚本想拿摄像机位置，直接读这个锚点即可，不需要互相引用。主角移动方向就是靠它算出来的（见 `Protagonist.cs` 的 `RecalculateMovement()`）。

## 3. 从 Play 开始：游戏启动流程

在编辑器里点 Play 后发生了什么？追这条链路：

```
Initialization.unity（唯一在 Build Settings 里的场景）
        │
        ▼
InitializationLoader.cs（SceneManagement/）
        │ 1. 通过 Addressables 加载 PersistentManagers 场景（叠加模式）
        ▼
PersistentManagers.unity（常驻管理器场景，切换关卡不销毁）
        │ 2. 加载 LoadEventChannelSO 并 RaiseEvent
        ▼
GameManager / QuestManager / 各种 Manager 就位
        │ 3. 通过 LoadEventChannelSO 加载 MainMenu
        ▼
主菜单 → 开始游戏 → 加载 Gameplay.unity + 某个 Location（如 Beach）
```

**关键文件**：
- `Assets/Scripts/SceneManagement/InitializationLoader.cs` — 启动入口
- `Assets/Scripts/Gameplay/GameManager.cs` — 开局逻辑（设置游戏状态、启动任务系统）
- `Assets/Scripts/SceneManagement/SceneLoader.cs` — 负责切换/卸载关卡场景

> 提示：Location 场景（Beach、Forest、Town_Inner 等）是通过 Addressables 按需加载的，`Scenes/Locations/` 下的 `*.unity` 不会全都在 Build Settings 里。

## 4. 主角 PigChef 解剖

主角预制体在 `Assets/Prefabs/Characters/PigChef.prefab`，挂了一整套组件。从上到下理解：

```
PigChef（根节点）
 ├── CharacterController      （物理移动：碰撞、重力）
 ├── Animator                 （播放动画，参数由 AnimatorParameterActionSO 设置）
 ├── StateMachine             （主角的大脑，引用 PigChef_TransitionTable.asset）
 ├── Protagonist.cs           （"输入缓存"：订阅 InputReader 事件，存下移动/跳跃等输入）
 ├── Health / Damageable / Attacker  （战斗相关）
 └── 子物体：视觉模型、特效、音效源等
```

### 数据流：输入 → 行为 → 表现

```
Input System (GameInput)
        │
        ▼
InputReader.cs          （把输入转成 C# 事件）
        │  JumpEvent / MoveEvent / AttackEvent...
        ▼
Protagonist.cs          （监听事件，把输入值存到 public 字段）
        │  movementInput / jumpInput / attackInput ...
        ▼
StateMachine Actions    （每个 ActionSO 读取这些字段，做出行为）
        │  例如 HorizontalMoveActionSO 用 movementInput 推动角色
        ▼
Animator / Audio / Particles   （表现层）
```

### 主角有哪些"状态"（`ScriptableObjects/StateMachine/Protagonist/States/`）

| 状态 | 说明 |
|------|------|
| `Idle` | 待机 |
| `Walking` | 行走 |
| `Sliding` / `MidSliding` | 滑铲（冲刺中/滑行中） |
| `JumpAscending` / `JumpDescending` | 上升 / 下落 |
| `IdleAttacking` / `WalkAttacking` / `Jump*Attacking` | 各姿态下的攻击 |
| `PickUp` / `Talk` / `Listen` | 拾取 / 对话 |
| `GettingHit` / `Dying` / `Killed` | 受伤 / 濒死 / 死亡 |

对应的**条件**（`Conditions/`）：`IsGrounded`、`IsMoving`、`IsHoldingJump`、`IsHoldingAttack`、`IsSliding`、`IsPlayerGettingHit`、`IsThisDead` 以及几个计时器条件（`Timer_*`，用于动画时长控制）。

> 💡 **动手实验建议**：打开 `PigChef_TransitionTable.asset`，配合右上角 `StateMachineDebugger`（编辑器窗口）查看实时状态切换，比读代码更直观。

### 主角相关的重要脚本（按阅读优先级）

1. `Assets/Scripts/Characters/Protagonist.cs` — **必读**，输入缓存与移动向量计算
2. `Assets/Scripts/Input/InputReader.cs` — 输入系统到事件的桥
3. `Assets/Scripts/Characters/StateMachine/Actions/HorizontalMoveActionSO.cs` — 最常用的移动 Action
4. `Assets/Scripts/Characters/StateMachine/Actions/RotateActionSO.cs` — 你当前打开的文件，角色转向
5. `Assets/Scripts/Characters/StateMachine/Actions/ApplyMovementVectorActionSO.cs` — 真正把向量写进 CharacterController

## 6. 推荐阅读顺序（分阶段）

### 🟢 第一阶段：跑通主线（1~2 小时）

目标是理解"游戏是怎么跑起来的"，**只看不深究**：

1. 读 `Protagonist.cs` 全文（主角入口，注释很全）
2. 读 `StateMachine/Core/StateMachine.cs` 的 `Update()` 和 `Transition()`
3. 读 `State.cs`（状态 = 动作 + 转换）
4. 读 `Input/InputReader.cs` 的前 80 行（事件定义）
5. 读 `Events/ScriptableObjects/` 里一个 EventChannel 的实现
6. 读 `SceneManagement/InitializationLoader.cs`（启动流程）

> 此时可以打开编辑器，选中场景里的 PigChef，用 StateMachineDebugger 看它在不同状态间跳转。

### 🟡 第二阶段：理解"行为即拼装"（2~3 小时）

目标：看懂一个具体行为（比如跳跃）是怎么从 SO 资产拼出来的：

1. 读 `StateMachine/ScriptableObjects/StateActionSO.cs`、`StateConditionSO.cs`、`StateSO.cs`、`TransitionTableSO.cs`（SO 层如何实例化运行时对象）
2. 在 `ScriptableObjects/StateMachine/Protagonist/` 里打开 `PigChef_TransitionTable.asset`，找到"Jump"相关状态
3. 对照看 `Actions/AscendActionSO.cs`、`Actions/DescendActionSO.cs`、`Actions/GroundGravityActionSO.cs`
4. 看 `Actions/HorizontalMoveActionSO.cs`、`Actions/ApplyMovementVectorActionSO.cs`、`Actions/RotateActionSO.cs`（移动三件套）

> 这一阶段结束，你就掌握了这个项目 80% 的"套路"：**任何新行为 = 新建一个 ActionSO + 在 TransitionTable 里接线**。

### 🔵 第三阶段：按兴趣深入（按需）

- 对**系统架构**感兴趣：`SaveSystem/`、`SceneManagement/`、`Events/`
- 对**玩法系统**感兴趣：`Inventory/`、`Quests/`、`Dialogues/`
- 对**敌人 AI**感兴趣：`Characters/NPC.cs`、`Critter.cs` + NPC 的 Actions
- 对**编辑器工具**感兴趣：`StateMachine/Editor/`、`EditorTools/`

## 7. 编辑器里的高效查找技巧

1. **找 Prefab 用的脚本**：右键某个 `.prefab` → 直接在 Inspector 里看组件；或 Ctrl+Shift+F 全局搜索类名。
2. **找 SO 资产引用了谁**：选中资产 → Inspector 下方可看被引用情况（或用 `右键 → Find References in Scene`，需安装第三方工具）。
3. **StateMachineDebugger**：`Window → 搜索 StateMachine`，运行时实时看状态切换，强烈推荐。
4. **Addressables**：`Window → Asset Management → Addressables → Groups`，看哪些资源是"可寻址"的（场景、预制体、音频等）。
5. **VS Code 里**：善用全局搜索（Ctrl+Shift+F），例如搜 `RaiseEvent` 看事件发射点，搜 `OnEventRaised` 看监听点。

## 8. 常见问题与踩坑

- **别把 `PigChef` 写成 `Pig Chief`**：搜索代码时用 `PigChef`。
- **改代码后行为没变？** 很多行为由 SO 资产驱动，改了代码要检查对应 `.asset` 资产里的配置是否引用了正确的 Action。
- **场景里找不到 PigChef？** 它在 `Prefabs/Characters/PigChef.prefab`，且是通过场景中的生成点或直接摆放在 Location 场景中的，先打开任意 `Locations/` 场景查看。
- **不要在 `Assets/Scripts/StateMachine/Core/` 随便改**：这是通用框架，很多行为依赖它的生命周期，改动影响面大。
- **新 Input System 报错？** 项目用的是新版 Input System，控制方案在 `Assets/Settings/` 下的 `GameInput.inputactions` 资产里（在 `Scripts/Input/GameInput.cs` 有对应生成代码）。
- **想加新主角动作**：正确姿势是 ① 在 `ScriptableObjects/StateMachine/Protagonist/` 新建 State/Action/Condition 资产 → ② 编辑 `PigChef_TransitionTable.asset` 连线，而不是改代码。
